Basic Integration

Damage Screen is designed for very fast integration in any project. Add the prefab to your scene and push health values with one line of code whenever local player health changes.

___________________________________________

1. Add the prefab



Drag and drop the main prefab into your scene:
Assets/Lovatto/DamageScreen/Content/Prefab/Main/Damage Screen (Blood).prefab
(Click here to ping) or any of the variations.

2. Send health updates (one line)



In your player health script, after any damage or heal operation, call:

bl_DamageScreen.UpdateHealth(currentHealth, maxHealth);

For beginner integration: currentHealth and maxHealth are not fixed words or placeholders. They should be the real health variables/parameters from your own player health script at the moment damage is applied.

Minimal damage example:

public void ReceiveDamage(int damageAmount)
{
    currentHealth = Mathf.Clamp(currentHealth - damageAmount, 0, maxHealth);
    bl_DamageScreen.UpdateHealth(currentHealth, maxHealth);
}
Important: UpdateHealth must be called with the local player values and a valid maxHealth greater than 0.

Using Included Player Health

If you prefer a ready-to-use health controller, the asset includes a basic player health component with damage, heal, death event, and optional regeneration.

Included script:
Assets/Lovatto/DamageScreen/Content/Scripts/Runtime/Systems/bl_PlayerHealth.cs
(Click here to ping)

How to use it:
1. Add bl_PlayerHealth to your player object.
2. Configure max health, start health, and regeneration in the Inspector.
3. Call TakeDamage or Heal from your gameplay logic.

playerHealth.TakeDamage(damageAmount);
playerHealth.Heal(healAmount);

The component already sends updates to Damage Screen internally, so you do not need to call UpdateHealth manually when using this script.

Damage Screen Settings

All gameplay behavior is controlled from a single ScriptableObject settings asset loaded at runtime from Resources.

Default settings asset:
Assets/Lovatto/DamageScreen/Resources/DamageScreenSettings.asset
(Click here to ping)

Blood Screen Settings


- bloodHealthThreshold: health percentage where blood starts appearing.
- DamageScreenFadeMode: keep blood synced to health or fade after delay.
- bloodFadeOutDelay / bloodFadeOutDuration: timing for auto fade mode.

Screen Alpha Display


- GradualByHealth: all overlays blend by current health.
- OnePerHit: one overlay pulse per hit (fade in -> hold -> fade out).
- Per-hit timing and intensity controls are exposed in the same section.

Near Death and Audio


- Configure heartbeat start/critical thresholds.
- Tune pulse speed and volume limits.
- Adjust max chromatic aberration for post-processing mode.

Modify Near Death Screen Effect



To customize the near-death look, edit this Volume Profile:
Assets/Lovatto/DamageScreen/Content/Prefab/Presets/NearDeathEffectVolume.asset
(Click here to ping)

Inside the profile you can tune values like color grading, vignette, chromatic aberration, and other post-processing parameters to match your game's style.

If useFastScreenEffect is enabled in settings, this Volume Profile is bypassed and the fast canvas overlay mode is used instead.

UI Customization

You can fully customize the visual style by editing the prefab UI references and replacing the included textures/animations.

Main prefab for UI editing:
Assets/Lovatto/DamageScreen/Content/Prefab/Main/Damage Screen.prefab
(Click here to ping)

Recommended workflow:
1. Duplicate the prefab before editing for safe iteration.
2. In bl_BloodDamageScreen, replace or reorder the screenAlphas overlays.
3. Adjust redOverlayAlpha for global tint intensity behavior.
4. Optional: assign or replace flashScreenAnimator for custom hit flash animation.
5. In bl_NearDeathEffect, tune heartbeat clip/source and near-death visuals.

Tip: Using multiple overlay images with varied shapes gives a more natural result than reusing one repeated texture.

Mobile Projects

For mobile projects, use the fast near-death mode. By default near death uses post-processing Volume effects, which are heavier for mobile GPUs.

In DamageScreenSettings > enable:
useFastScreenEffect = true

When enabled:
- Post-processing near-death volume is disabled.
- A lightweight canvas alpha overlay is used instead.
- You keep the same health integration API.

Mobile optimization checklist:
1. Keep overlay textures compressed and sized for target devices.
2. Prefer OnePerHit mode if you want shorter blood spikes.
3. Reduce pulse speed and maximum volumes if needed for battery/performance budgets.

Respawn and Reset

When players respawn or restart rounds, clear visual/audio state to avoid carrying old damage feedback into a fresh life.

Use these reset calls at respawn time:

bl_DamageScreen.Instance.ResetScreen();

After reset, push the current health again so the system starts from the proper state:

bl_DamageScreen.UpdateHealth(currentHealth, maxHealth);
Common use cases: - Respawn systems - Round restart - Scene reload - Checkpoint restore

Troubleshooting

Quick checks for the most common setup issues.

If you see no effect


- Confirm one active Damage Screen prefab exists in the scene.
- Confirm your health script calls UpdateHealth after every health change.
- Confirm maxHealth is greater than 0.
- Confirm DamageScreenSettings.asset exists in a Resources folder.

If heartbeat does not play


- Ensure the near-death component has an AudioSource.
- Assign a heartbeat clip in the near-death component or AudioSource.
- Lower health below the configured threshold to trigger playback.

Multiplayer note


Only call UpdateHealth for the local player UI. Remote players should not drive your local screen feedback.
